# CLAUDE.md

Статичный hero-экран Exelena Football Academy: HTML/CSS/JS без сборки, игрок поворачивает голову за курсором. Обзор и команды — в README.md; здесь то, что нужно знать при изменениях.

## Запуск и проверка

- `python3 -m http.server 8765` из корня, страница — http://127.0.0.1:8765/
- Pixel-perfect сверка: `python tools/compare.py` (Playwright, канал `chrome` — системный Google Chrome). Печатает дельты bbox элементов «рендер − референс» в px, пишет `.work/shot.png` и `.work/blend.png`. После любой правки десктопной вёрстки — прогнать и держать дельты в пределах ±1–2 px.
- `--mouse X` — снимок с курсором в точке X (проверка поворота головы).
- Мобильные проверять на 390×844 и 820×1180 (full page), убедиться, что `scrollWidth == clientWidth`.
- Python-зависимости — `tools/requirements.txt`; ставить в отдельный venv, не в систему.

## Вёрстка (assets/css/style.css)

- Десктоп (≥1024px) — абсолютное позиционирование на сетке макета 1591×989. Все размеры только как `calc(N * var(--k))`, где N — пиксели макета, `--k = 100vw / 1591`. Не вводить px/rem напрямую в десктопные правила.
- Координаты сняты с `references/reference.png`; числа вида `left: calc(1329 * var(--k))` — это пиксели макета, их и сверять.
- Строки заголовка EXELENA / FOOTBALL / ACADEMY в макете разного кегля (91 / 81 / 75) — это намеренно, не «выравнивать».
- Пункты навигации имеют индивидуальные `margin-left` (nth-child) — подгонка под макет.
- <1024px: `--k: 1px`, компоненты сохраняют размеры макета, блоки в потоке. В медиазапросе `.hero__content > *` сбрасывает `position/left/top` — без `left/top: auto` блоки уезжают за пределы страницы (уже ловили на `.stats`).
- Рамки со срезанными углами (`.stats`, `.card`) — inline SVG `polygon` с `vector-effect: non-scaling-stroke` + заливка через `clip-path` на `::before`.
- Иконка-стрелка используется как CSS-маска (`.icon--arrow`, цвет = `currentColor`); остальные иконки — `<img>`.

## Игрок (assets/js/main.js + assets/img/player/)

- Один `<canvas>` 1440×1211 (координаты «canvas px»): `body.webp` рисуется в `BODY`, текущий кадр — в `FRAMES`. Константы `FRAMES`/`BODY` в main.js обязаны совпадать с выводом `tools/build_player.py export`.
- Порядок кадров: `f00` — смотрит вправо (от зрителя), `f18` — нейтральный (кадр видео 52), `f40` — влево. Курсор левее `HEAD.x` → индекс растёт.
- Размещение canvas на странице — `.hero__player` (left 334, top 9, ширина 1333 в пикселях макета) — подобрано по наложению на референс.
- Нижний край кадров растушёван в `body.webp`; тело выровнено с кадром 52 со сдвигом (0,0) — при перегенерации торса это нужно перепроверить.

## Ассеты

- В проекте только WebP. PNG-исходники от codex лежат в `.work/gen/` (в git не входит), конвертация — `tools/build_images.py` (альфа из яркости по чёрному фону, обрезка, даунскейл).
- Картинки и иконки генерируются через codex CLI, иконки — в PNG на чистом чёрном фоне (SVG codex рисует плохо). Шаблон вызова:
  `codex exec --skip-git-repo-check --sandbox workspace-write -C <dir> -i <ref.png> - < tools/prompts/<name>.txt`
  Промпты лежат в `tools/prompts/`; при правке ассета сохранять обновлённый промпт туда же.
- Для фона, повторяющего референс, работает только формулировка «EDIT/inpainting, сохрани всё на местах» (`prompts/background.txt`); «сгенерируй похожую сцену» даёт другую композицию.
- codex возвращает картинки своего размера (например 1254×1254 или 1368×1149) — всегда ресайзить к целевому и проверять выравнивание.
- `tools/build_player.py` детерминированно воспроизводит `assets/img/player/*` (проверено: побайтовое совпадение). Шаги: `frames → segment → matte → input`, затем ручной вызов codex для торса, затем `export`.
- rembg: используется `isnet-general-use`. `birefnet-*` на этой машине (7 ГБ RAM) падает по OOM.
- `references/` (макет и видео) не публикуются — в `.gitignore`.

## Известные ограничения

Игрок из видео отличается от макета (ракурс, свет, скошенный взгляд во фронтальных кадрах, исходник 752×416 растянут в 1.8 раза); фон сгенерирован и совпадает по композиции, не попиксельно.
